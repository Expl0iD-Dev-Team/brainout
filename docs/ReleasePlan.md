# План выпуска: онлайн-версия для знакомых

**Цель:** небольшая группа знакомых играет на Android через ваш собственный backend. APK раздаётся через GitHub Releases, Google Play не используется.

**Кто что делает:** код, команды и инструкции готовятся в репозитории. Настройку домашнего сервера и все тесты на телефонах выполняет владелец проекта.

**Вне объёма:** Google Play, платежи, Battle Pass, античит, масштабирование, голосовой чат.

## Этапы

| Этап | Содержание | Готово, когда |
|---|---|---|
| 0. Сборка | сборка из чистого клона, GitHub Actions, ключ подписи | новый коммит сам даёт рабочий APK |
| 1. Backend | развёртывание на домашнем сервере ([ServerSetup.md](ServerSetup.md)): закрытие портов, HTTPS на своём CA, свои пароли, настоящий `market`, бэкапы | телефон входит по HTTPS, после перезагрузки всё поднимается само |
| 2. Матчи | серверы `freeplay`, `main`, `duel`, онлайн-APK, чистка меню | два телефона играют в одном матче, прогресс сохраняется |
| 3. Управление | кнопка «Назад» и пауза, слоты оружия, прицел, чат, панель действий, масштаб интерфейса, замена правой кнопки мыши | весь путь проходится без клавиатуры и мыши |
| 4. Стабильность | обновление данных при обновлении APK, прогресс первого запуска, сворачивание, потеря сети, журнал падений | час игры без падений на двух телефонах |
| 5. Выпуск | слияние в `master`, инструкции, `v1.0.0`, неделя теста на 3–5 знакомых | все знакомые играют |

## Статус этапа 0

Этап завершён. APK с релизной подписью и серверный архив, собранные в GitHub Actions, проверены на эмуляторе (Android 37, x86_64): подключение через `brainout://`, загрузка данных и вход в матч freeplay работают, стик реагирует. На реальном телефоне сборка ещё не проверялась.

## Статус этапа 1

Код и инструкция ([ServerSetup.md](ServerSetup.md)) готовы. Весь путь проверен на Ubuntu 22.04 в WSL с эмулятором:
- развёртывание с нуля;
- вход в онлайн-APK по HTTPS с собственным CA;
- лобби на сервере, запущенном контроллером;
- сохранение профиля;
- резервная копия и восстановление;
- перезапуск сервера.

Не проверены настоящий роутер с NAT и реальный телефон: это делает владелец на своём сервере.

По ходу исправлено падение клиента в онлайн-лобби. `SoundEffectData.updateSound()` и три таких же класса рекурсивно повторяли `play()`, пока Android отказывал в запуске звука, и переполняли стек.

## Статус этапа 2

Режимы, которые клиент запрашивает у game master, теперь развёртываются:

| Сервер | Режим | Аргументы |
|---|---|---|
| `lobby` | лобби | `--mode lobby --settings server-lobby.json --map maps/lobby.map` |
| `main` | Quick Play: deathmatch, gungame и другие режимы по ротации карт, 6 ботов | `--settings server-settings.json --maps maps-set.json` |
| `freeplay` | Free Play, до 4 игроков | `--mode free --settings server-free.json --map freeplay-maps.shuffle` |
| `duel` | дуэль | `--mode duel --settings server-duel.json --map maps/duel.map` |

`custom` (карты из Steam Workshop) без Steam работать не может и не развёртывается.

Проверено на WSL с эмулятором:
- онлайн-APK проходит лобби и Quick Play до матча deathmatch с ботами: появление на карте, движение и стрельба работают;
- matchmaking ставит второго игрока в ту же комнату (проверено через API);
- серверы `freeplay` и `duel` запускаются по запросу.

Игру двух людей на двух устройствах проверяет владелец на телефонах: два эмулятора на тестовой машине не помещаются в память.

Исправлено по ходу:
- **Падение клиента в матче.** Android подсовывает свой встроенный `org.json`, а в нём нет `put(String, float)`, `optFloat` и `JSONObject.getNames`. Игра падала при первом же уроне. Остальные вызовы `org.json` сверены с `android.jar`.
- **Адреса в discovery.** `deploy.sh` при смене адреса сервера оставлял в discovery старые адреса: сервис держит их в Redis.
- **Устаревший хост.** Хост с прежним адресом оставался «активным», и game master отправлял туда запуск игр.
- **Реклама Steam** в лобби убрана.

## Статус этапа 3

Игра проходится пальцами, без клавиатуры и мыши:
- **Масштаб интерфейса.** Меню, надписи и мир отрисовываются так, будто короткая сторона экрана равна 720 точкам. На телефоне с высотой 1080 px всё стало в 1,5 раза крупнее.
- **«Назад».** Системная кнопка «Назад» закрывает окна и чат, а в матче открывает меню паузы с выходом в лобби. Игра от неё больше не закрывается.
- **Кнопки в матче.** Справа внизу расположены слоты оружия 1–4 и «Последнее», под ними «Оружие», «Перезарядка», «Присесть» и «Использовать». Слева вверху расположены «Меню», «Игроки», «Чат», «Прицел» и «Ещё». Панель «Ещё» содержит «Выбросить оружие», «Выбросить патроны», «Разрядить», «Режим огня» и «Сменить команду». Надписи переведены на английский и русский.
- **Ввод текста.** Нажатие на поле ввода открывает системное окно Android с текущим текстом. Кнопка OK в этом окне заменяет текст в поле, а в чате сразу отправляет сообщение.
- **Правая кнопка мыши.** Магазин заряжается перетаскиванием патронов, карту в мини-игре берут перетаскиванием на своё место. Тайник в квартире во Free Play открывается коротким нажатием на него.
- В онлайн-сборке кнопка «Direct Connect» скрыта: игры находятся через сервер.

Проверено на эмуляторе в Quick Play: каждая кнопка, «Назад» в меню и в матче, чат в лобби и в матче. Открытие тайника в квартире не проверялось: для этого нужно купить квартиру во Free Play.

Исправлено по ходу:
- **Пакеты не обновлялись вместе с APK.** Данные, скопированные при первом запуске, оставались старыми после обновления, и новые надписи не появлялись. Теперь пакеты копируются заново после каждой установки или обновления APK, через временный файл.
- **Координаты указателя в квартире** не учитывали масштаб интерфейса.

## Статус этапа 4

- **Журнал падений.** При падении игра записывает отчёт: ошибку, модель телефона, Android и последние 200 строк журнала. При следующем запуске она предлагает отправить отчёт через системное меню «Поделиться» (Telegram, почта и т. п.). Отчёт предлагается один раз.
- **Сворачивание.** Android замораживает свёрнутую игру через несколько секунд, и сервер отключал игрока примерно через 30 секунд. Теперь, пока игра свёрнута, работает служба с уведомлением «Связь с матчем держится ещё несколько минут». Она держит соединение до 5 минут. Кроме того, ответ на ping сервера теперь уходит из сетевого потока, а не из потока отрисовки. Свёрнутая игра ничего не рисует, поэтому раньше сервер через 30 секунд без ответа выкидывал игрока и засчитывал ему дезертирство.
- **Потеря сети.** Клиент и сервер ждут переподключения 45 секунд вместо 15: переход с Wi-Fi на мобильный интернет занимает больше 15 секунд. Если связь не вернулась, игра показывает «Connection error», а после OK возвращается в лобби. На эмуляторе возврат занимает 22 секунды.
- **Системные настройки.** Смена темы, размера шрифта или режим разделённого экрана больше не перезапускают игру. Ссылка `brainout://` открывает уже запущенную игру, а не вторую копию.
- **Кэш звуков.** Игра при каждой загрузке распаковывала звуки в новые временные файлы и не удаляла их: после нескольких сессий набралось 6883 файла и 432 МБ. Теперь каждый звук распаковывается один раз, а старые файлы удаляются при запуске.
- **Время загрузки** пакетов записывается в журнал: `Packages loaded in N s`.

Обновление сервера обязательно: время ожидания переподключения задаётся на сервере тоже. Нужен серверный бандл из этого коммита или новее.

Проверено на эмуляторе:
- отчёт о падении записывается, при следующем запуске появляется диалог, и открывается меню «Поделиться»;
- игра, свёрнутая в лобби на 90 секунд, остаётся подключённой (без службы соединение рвалось через 36 секунд);
- игра, свёрнутая в матче на 2,5 минуты, остаётся в матче (раньше сервер выкидывал через 30 секунд без ответа на ping);
- после 20 секунд без сети (режим полёта) игра сама переподключается в тот же матч через 4 секунды после возвращения сети;
- первая загрузка после запуска занимает 612–625 секунд, следующие — 3 секунды. Почти всё время уходит на `SoundPool.load`, декодирование примерно 800 звуков: эмулятор декодирует их программно и без звуковой карты.

Владелец проверяет на телефонах:
- сколько длится первая загрузка: время от нажатия на заставку до лобби;
- сворачивание в матче на 1–2 минуты и возврат;
- переключение Wi-Fi ↔ мобильный интернет во время матча;
- час игры вдвоём без падений.

## Сборка

Нужны JDK 17 и Android SDK (путь в `local.properties` или `ANDROID_HOME`).

```bash
# APK из чистого клона; данные соберутся сами при первом запуске
./gradlew :android:assembleDebug -PwithAndroid

# после изменений в data/
./gradlew :android:assembleDebug -PwithAndroid -PrebuildData

# серверный jar и данные
./gradlew make_data server:dist
```

На Windows Gradle скачивает Python 3.10 с CDN автора оригинальной игры (`cdn.brainout.org`). Если CDN недоступен, укажите свой Python 3.10 с пакетами `PyCryptodome`, `cffi` и [hjson-py](https://github.com/desertkun/hjson-py):

```bash
./gradlew make_data -PdataPython=/путь/к/python
```

Если машина выходит в интернет через прокси, пропишите его в `~/.gradle/gradle.properties` (`systemProp.https.proxyHost`, `systemProp.https.proxyPort`): Java не читает `HTTPS_PROXY`.

## GitHub Actions

Workflow [build.yml](../.github/workflows/build.yml) собирает APK и серверный архив:

- **при каждом пуше и pull request** они доступны как артефакты запуска 14 дней;
- **при теге `v*`** они публикуются как GitHub Release.

| Настройка | Где | Что делает |
|---|---|---|
| `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` | Secrets | релизная подпись; создаются скриптом `scripts/setup-release-signing.sh`. Без них сборка подписывается отладочным ключом, а сборка по тегу падает |
| `BRAINOUT_ENV_SERVICE` | Variables | адрес backend. Без неё APK собирается в offline-варианте с прямым подключением по IP |

Файлы ключа `android/brainout-release.jks` и `android/keystore.properties` держите в резервной копии: секреты GitHub нельзя прочитать обратно, а без ключа новую версию нельзя установить поверх старой.
