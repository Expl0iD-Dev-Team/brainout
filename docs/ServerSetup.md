# Запуск backend на своём сервере

Инструкция для Ubuntu 22.04 за NAT, со статическим IP и без домена. Все команды выполняются на сервере, если не сказано иное.

## Как это устроено

| Что | Порт | Снаружи |
|---|---|---|
| Сервисы Anthill (вход, профиль, магазин, матчмейкинг и т. д.) | `127.0.0.1:9500–9519` | нет |
| nginx с HTTPS перед сервисами, которые нужны игре | `19501–19519` TCP | **да** |
| Игровые комнаты: TCP, UDP и HTTP для загрузки карт | `38000–38020` TCP и UDP | **да** |
| MySQL, Redis, RabbitMQ, Grafana, админка Anthill | `127.0.0.1` | нет |

- **HTTPS без домена.** Сертификат выпускает собственный центр сертификации (CA), созданный на сервере. Его открытая часть встраивается в APK, поэтому приложение доверяет серверу, а браузеры выдают предупреждение. Это ожидаемо.
- **Пароли.** `deploy.sh` генерирует их случайно и хранит в `deploy/anthill/state/secrets.env`. Стандартный пароль `anthill` у учётной записи `root` заменяется.
- **Обновления.** Повторный запуск `deploy.sh` безопасен: так же разворачивается новая версия сервера.

## 1. Подготовить сервер

Docker нужен из официального репозитория: версия Compose из пакетов Ubuntu слишком старая.

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl git openssl python3
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker "$USER"
```

Выйдите из сессии и войдите снова, чтобы группа `docker` применилась. Проверьте, что Compose не старше 2.24.4:

```bash
docker compose version
```

Порты `3000`, `3306`, `5672`, `15672`, `8086`, `9500–9519`, `19501–19519` и `38000–38020` на сервере должны быть свободны. Если эта команда что-то вывела, сообщите:

```bash
ss -ltnu | grep -E ':(3306|5672|15672|3000|8086|95[01][0-9]|195[01][0-9]|380[0-2][0-9]) '
```

## 2. Код и сборка сервера

```bash
cd ~
git clone https://github.com/Expl0iD-Dev-Team/brainout.git
cd brainout
```

Скрипты развёртывания берутся из `master`. Пока изменения не слиты, переключитесь на рабочую ветку: `git checkout claude/peaceful-mccarthy-rigm7y`.

Серверная сборка — это файл `brainout-server-<версия>.tar.gz`. Для выпущенной версии он лежит в релизе вместе с APK ([Release.md](Release.md)). Промежуточные сборки скачиваются на странице [Actions](https://github.com/Expl0iD-Dev-Team/brainout/actions/workflows/build.yml) (раздел Artifacts) и распакуйте его. Внутри лежат APK, серверный архив и `SHA256SUMS.txt`. Перенесите серверный архив на сервер, например так:

```bash
scp brainout-server-*.tar.gz <пользователь>@<сервер>:~/
```

## 3. Настройка

```bash
cp deploy/anthill/config.env.example deploy/anthill/config.env
nano deploy/anthill/config.env
```

Задайте:
- `PUBLIC_HOST` — ваш статический IP;
- `SERVER_BUNDLE` — полный путь к архиву, например `/home/<пользователь>/brainout-server-0.0.3-abc1234.tar.gz`.

Остальное можно оставить как есть.

## 4. Развёртывание

```bash
./deploy/anthill/deploy.sh
```

Первый запуск долгий: скачиваются образы Docker общим объёмом в несколько гигабайт. В конце скрипт выполнит проверки, выведет список портов для роутера и настройки для APK.

Если запуск упал, пришлите последние строки вывода. Повторить проверку можно в любой момент:

```bash
./deploy/anthill/check.sh
```

## 5. Роутер

Пробросьте на этот сервер с теми же номерами портов:

| Порты | Протокол |
|---|---|
| `19501–19519` | TCP |
| `38000–38020` | TCP **и** UDP |

UDP обязателен: без него игра войдёт в матч, но не сможет играть.

Проверить нужно извне, например с телефона через мобильный интернет. Через домашний Wi-Fi обращение к собственному внешнему IP работает, только если роутер поддерживает NAT loopback. Откройте в браузере телефона адрес ниже, подставив свой IP:

```
https://<ваш IP>:19503/brainout/valpha2
```

Браузер предупредит о сертификате, это нормально. После подтверждения должна появиться строка `{"discovery": "https://<ваш IP>:19502"}`.

## 6. Онлайн-APK

APK должен знать адрес сервера и доверять вашему CA. Это две переменные в настройках репозитория. Их можно задать на компьютере с `gh`. Подставьте свой IP вместо `<ваш IP>`, а сертификат скопируйте с сервера (`deploy/anthill/state/tls/ca.crt`):

```bash
gh variable set BRAINOUT_ENV_SERVICE --repo Expl0iD-Dev-Team/brainout --body "https://<ваш IP>:19503"
```

```bash
gh variable set BRAINOUT_SERVER_CA --repo Expl0iD-Dev-Team/brainout < ca.crt
```

Либо через сайт: Settings → Secrets and variables → Actions → Variables. В `BRAINOUT_SERVER_CA` вставьте содержимое `ca.crt` целиком, вместе со строками `BEGIN` и `END`.

Следующая сборка в Actions выдаст онлайн-APK.

**Не меняйте CA без нужды.** `ca.crt` создаётся один раз и встроен в APK. Если удалить `state/tls/ca.key`, понадобится новый APK для всех игроков.

## 7. Резервные копии

Копия создаётся в `/var/backups/brainout`, хранятся последние 14 дней. В неё попадают:
- база: аккаунты, профили, магазин;
- папка `state/`: пароли и ключ CA;
- ключи Anthill.

Нужен `sudo`, потому что часть файлов создана Docker от имени root.

```bash
sudo ./deploy/anthill/backup.sh
```

Чтобы копия делалась каждую ночь, откройте `sudo crontab -e` и добавьте строку, подставив свой путь к репозиторию:

```
30 4 * * * /home/<пользователь>/brainout/deploy/anthill/backup.sh >> /var/log/brainout-backup.log 2>&1
```

Копии на том же диске не спасут при поломке диска. Периодически переносите `/var/backups/brainout` на другую машину.

Восстановление базы удалит всё, что появилось после этой копии:

```bash
sudo ./deploy/anthill/restore.sh /var/backups/brainout/db-<время>.sql.gz
```

Если сервер собирается с нуля, сначала распакуйте `state-<время>.tar.gz`: папку `state` в `deploy/anthill/`, папку `keys` в `../anthill-dev/dev/`. Затем запустите `deploy.sh` и `restore.sh`.

## 8. Обслуживание

| Задача | Команда |
|---|---|
| Новая версия сервера | укажите новый архив в `SERVER_BUNDLE` и запустите `./deploy/anthill/deploy.sh` |
| Сменился внешний IP | исправьте `PUBLIC_HOST`, запустите `deploy.sh`, обновите переменную `BRAINOUT_ENV_SERVICE` и выдайте игрокам новый APK. CA остаётся прежним |
| Больше одновременных игр | каждая игра занимает 3 порта из `PORTS_FROM`–`PORTS_TO`: 21 порт хватает на 7 игр, включая лобби. Расширьте диапазон и проброс в роутере |
| Состояние | `./deploy/anthill/check.sh` |
| Логи сервиса | `docker logs --tail 100 anthill_login`, имя контейнера можно взять из `docker ps` |
| Логи игровых серверов | `ls ../anthill-dev/dev/data/game-controller/logs` |
| Перезагрузка сервера | ничего делать не нужно: контейнеры поднимаются сами. Первые 1–2 минуты контроллер перезапускается, пока не поднимется сервис входа, и `check.sh` в это время может выдавать ошибки |

Сервер и APK должны быть из одного запуска Actions: в них одинаковые игровые данные.

**Админка Anthill** доступна только с самого сервера. С компьютера откройте туннель и зайдите на `http://localhost:9500`:

```bash
ssh -L 9500:127.0.0.1:9500 <пользователь>@<сервер>
```

Логин `root`, пароль `ROOT_PASSWORD` из `deploy/anthill/state/secrets.env`. Админка для игры не нужна, это инструмент для отладки.

## Что проверено

Инструкция целиком пройдена на Ubuntu 22.04 (в WSL) с Docker 29 и Compose v5. Адресом сервера был адрес, по которому эмулятор Android видит компьютер.

| Сценарий | Результат |
|---|---|
| Установка Docker командами из раздела 1 | работает |
| `deploy.sh` на чистой системе, одним запуском | около 2,5 минуты при уже скачанных образах, все проверки пройдены |
| Онлайн-APK: вход по HTTPS с нашим CA, лобби, стартовый профиль, сохранение имени игрока | работает |
| Резервная копия, полное удаление, развёртывание из `state`, восстановление базы | игрок и его профиль вернулись, клиент вошёл в прежний аккаунт |
| Перезапуск сервера | всё поднимается само примерно за 2 минуты |

`deploy.sh` сам обходит найденные ошибки `anthill-dev`:
- у скриптов контейнеров нет права на исполнение;
- сервисы store и game master не создают часть своих таблиц;
- контроллер ищет сервисы по внешним адресам;
- `collectd` не запускается.

Матчи Quick Play и Free Play, переподключение и сворачивание проверены на эмуляторе на этапах 2–4 ([ReleasePlan.md](ReleasePlan.md)).

**Не проверены:**
- настоящий роутер с NAT;
- игра с реального телефона.
