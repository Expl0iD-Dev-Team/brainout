# Выпуск и обновление

Инструкция для организатора: как выпустить версию, раздать её знакомым и выпускать обновления. Сервер уже должен быть развёрнут по [ServerSetup.md](ServerSetup.md).

## Важно про публичность

Репозиторий на GitHub публичный, а в APK зашит адрес вашего сервера. На сервере работает анонимный вход, поэтому любой, у кого есть APK, может зайти на сервер и играть.

Поэтому Actions по тегу создаёт **черновик** релиза. Его видят только участники репозитория с правом записи. APK раздаётся знакомым напрямую, например в Telegram. Публиковать черновик не нужно. Если всё же опубликовать, скачать APK сможет кто угодно.

Файлы обычных сборок в Actions (раздел Artifacts) скачиваются любым вошедшим на GitHub пользователем, пока не истекут через 14 дней. После того как заданы переменные `BRAINOUT_ENV_SERVICE` и `BRAINOUT_SERVER_CA`, в этих файлах тоже есть адрес сервера.

## Перед первым выпуском

- [ ] Сервер развёрнут, `./deploy/anthill/check.sh` проходит без ошибок.
- [ ] Порты проброшены в роутере. Проверено с телефона через мобильный интернет: страница `https://<ваш IP>:19503/brainout/valpha2` отвечает (раздел 5 ServerSetup).
- [ ] Заданы переменные `BRAINOUT_ENV_SERVICE` и `BRAINOUT_SERVER_CA` (раздел 6 ServerSetup).
- [ ] Ночная резервная копия настроена (раздел 7 ServerSetup).
- [ ] Ключ подписи APK сохранён вне компьютера: `android/brainout-release.jks` и пароль к нему. **Без этого ключа обновления не установятся поверх**, и всем придётся удалять игру.
- [ ] Проверки этапа 4 на телефонах пройдены (список в [ReleasePlan.md](ReleasePlan.md#статус-этапа-4)), найденные проблемы исправлены.

## Выпуск версии

На примере `v1.0.0`.

1. **Слить изменения в `master`.** Примите pull request из рабочей ветки на GitHub (кнопка Merge).
2. **Поставить тег** на компьютере с клоном репозитория:

   ```bash
   git checkout master
   ```

   ```bash
   git pull
   ```

   ```bash
   git tag -a v1.0.0 -m "BrainOut 1.0.0"
   ```

   ```bash
   git push origin v1.0.0
   ```

3. **Дождаться сборки.** Через 5–10 минут в [Releases](https://github.com/Expl0iD-Dev-Team/brainout/releases) появится черновик «BrainOut 1.0.0» с файлами:
   - `brainout-1.0.0.apk`;
   - `brainout-server-1.0.0.tar.gz`;
   - `SHA256SUMS.txt`.

   Текст черновика берётся из `docs/releases/v1.0.0.md`.
4. **Обновить сервер той же версией.** Сервер и APK должны быть из одного релиза: в них одинаковые игровые данные, а некоторые настройки, например время ожидания переподключения, действуют на обеих сторонах. Скопируйте архив на сервер, затем на сервере укажите его в `SERVER_BUNDLE` в `deploy/anthill/config.env` и запустите:

   ```bash
   ./deploy/anthill/deploy.sh
   ```

5. **Проверить на своём телефоне.** Установите APK поверх тестового, войдите в лобби, сыграйте в Quick Play и напишите в чат.
6. **Раздать.** Отправьте знакомым APK и ссылку на [памятку игроку](Players.md) или её текст.

Номер сборки Android (`versionCode`) — это номер запуска Actions. Он растёт сам, поэтому каждая следующая версия ставится поверх предыдущей.

## Обновление

1. Исправления делаются в ветке и попадают в `master` через pull request.
2. Добавьте заметки к выпуску: `docs/releases/v1.0.1.md`.
3. Поставьте тег `v1.0.1` так же, как выше. Сервер обновите **тем же** архивом из релиза, даже если менялся только клиент.
4. Раздайте APK. Игроки ставят его поверх старой версии. Первая загрузка после обновления снова долгая.

Откатить APK на старую версию поверх новой нельзя: Android не ставит меньший `versionCode`. Если выпуск неудачный, выпустите исправление следующим номером. Сервер можно вернуть на прошлый архив сразу, но тогда пусть игроки до исправления не обновляются.

## Тестовая неделя

3–5 знакомых, 7 дней. Цель: собрать падения и неудобства до того, как звать остальных.

| Дни | Что просим сделать |
|---|---|
| 1 | установить, засечь время первой загрузки (от заставки до лобби), освоиться с управлением в «Тренировке» |
| 2–3 | Quick Play вместе, минимум двое в одном матче. Чат, смена оружия, кнопки панели «Ещё» |
| 4–5 | Free Play вместе, инвентарь, квартира и тайник, если доберутся |
| 6 | свернуть игру посреди матча на минуту, переключить Wi-Fi на мобильный интернет |
| 7 | свободная игра, хотя бы час подряд |

Каждый день организатор:
- запускает `./deploy/anthill/check.sh`;
- смотрит, нет ли новых падений игровых серверов: `ls -lt ../anthill-dev/dev/data/game-controller/logs | head`;
- собирает отчёты о падениях и ведёт список проблем, например в issues на GitHub.

Неделя пройдена, когда:
- все участники хотя бы раз сыграли вместе;
- за последние 2 дня не было новых падений;
- нет проблем, мешающих играть.
